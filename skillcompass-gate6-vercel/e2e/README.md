# اختبارات QA المتصفحية (Playwright)

تشغّل Chromium حقيقياً على `index.html` عبر خادم محلي على `127.0.0.1`. كل الطلبات الخارجية محجوبة، ولا تُستخدم أي مفاتيح أو خدمات خارجية.
هذه الاختبارات **ليست ضمن CI** (بيئة CI لا تثبّت Chromium)، وتُشغَّل محلياً.

## المتطلبات
- Node.js `26.x` (LTS مدعوم، ويطابق Node 24 في CI). Playwright 1.63 يشترط Node 20 أو أحدث.
- npm (المدير الوحيد المعتمد في هذا المشروع: الملف `package-lock.json` يخصه).

## التثبيت من نسخة نظيفة
هذا الفرع لا يحتوي ملف قفل مؤقتًا غير موثوق. يشغّل Workflow باسم `QA V6 Node 26 Validation` توليد `package-lock.json` بواسطة npm من السجل العام ثم يرفعه كـArtifact للمراجعة. بعد مراجعة القفل وإضافته إلى الفرع، نفّذ من داخل `skillcompass-gate6-vercel/`:

```bash
npm ci                          # يثبّت playwright@1.63.0 بالإصدار المقفل في package-lock.json
npx playwright install chromium # يحمّل Chromium (مرة واحدة لكل جهاز)، ويُعادل: npm run qa:install-browser
npm run test:e2e:qa             # يشغّل اختبارات QA على 390×844 و1440×900
```

- `npx playwright install chromium` يحتاج وصولاً إلى خوادم تحميل Playwright. يُنفَّذ من مجلد المشروع حتى تُستخدم النسخة المحلية من Playwright.
- يحفظ المتصفح في المسار الافتراضي لـPlaywright، أو في `PLAYWRIGHT_BROWSERS_PATH` إن حُدّد.
- Playwright لا يحمّل المتصفح أثناء `npm ci`، لذلك خطوة تثبيت Chromium منفصلة ويجب تنفيذها مرة واحدة.

## ما تغطيه
- التسجيل الجديد دون كلمة مرور، وعدم ظهور كلمة المرور في التخزين أو Console.
- Migration لملف قديم يحتوي `password` مع الحفاظ على التقدم وSkillCoins.
- رحلة التسويق كاملة: رصيد صفر ← الدروس ← كسب العملات ← العودة ← خصم مرة واحدة ← متابعة.
- Refresh حقيقي لاستعادة قيم الإنفاق (5 و3)، ثم خصم صحيح (10 − 8 = 2).
- اكتمال جميع دروس التسويق دون العودة إلى الدرس الأول.
- تبديل المهارة عبر الويزارد الحقيقي مع بقاء تقدم كل مهارة منفصلاً بعد Refresh.
- بيانات تقدم تالفة (`null`، نصوص، أنواع خاطئة): التحميل يعمل وSkillCoins لا تضيع.
- فحص Console وأخطاء الصفحة وفشل تحميل الملفات المحلية.

## قيد الترحيل المعلن
المصفوفات `completedLessons` و`quizPassedLessons` الموجودة قبل فصل التقدم حسب المهارة تُنسب إلى المهارة الحالية للملف عند أول تحميل. هذا لا يحذف أي بيانات، لكن تقدماً قديماً اختلط بين مهارتين قبل هذا الإصلاح لا يمكن فصله بدقة.
